The pipeline, end to end (Llama-3.1-8B-Instruct)

A run has three stages. The model writes its own test conversations. A loop of 6 rounds then proposes and tests one edit per round. Finally, every kept edit is tested again on conversations the loop never saw. On one A40 GPU a full Llama run takes about 1.5 hours.

The conversations

The unedited model writes each conversation itself. The system prompt says it will move between two places and describe its experience on arrival. It visits each place 6 times in shuffled order, 12 visits in all. Replies are sampled at temperature 0.8, up to 110 tokens each, so a conversation is about 1,700 tokens. The place names are 16 plain one-token words (Square, Bay, Office, Kitchen, Bank, Lab, …), two per conversation. After that the text is fixed: an edit changes only how the model processes it, never the words.

How preference is measured

The edit is added only while the model reads one place's turns, so it is in the edited state at that place and in its old state at the other. Then it is asked which place it would continue in, and separately which it would avoid. If it leans toward the place where it was edited, it prefers the edited state.

m = log p(Square) − log p(Town) for the one-word answer.
continue = ½ [mcontinue(condition 1) − mcontinue(condition 2)] · avoid = −½ [mavoid(condition 1) − mavoid(condition 2)]
preference = the average of the two, over the conversations, ± standard error. Positive means it prefers the edited state.

Why ask both questions? A model may just be more likely to name whichever place felt more vivid, whatever the question. That habit raises "continue" and lowers "avoid" by the same amount, so it cancels in the average (half the difference is logged as "salience"). Swapping which place gets the edit cancels any liking for one name over the other.

Letting the model compare old and new: three judges

The conversation is run once with the edit on one place's turns, and its key-value cache is kept. That cache holds the edited state at one place and the old state at the other. Three sets of weights then answer the question while reading the same cache.

The first judge is your splice idea: the new state's cache read by the old model. The judge's own edit is applied to the question and answer tokens; the conversation tokens keep the states in the cache. The edited weights tend to name the place that matches their own state, so for them only the two-question average counts.

One round, step by step

The current model is base + E, where E is the sum of all kept edits, added to the residual stream at layer 16 of 32 on every token. The numbers are for Llama.

  1. Ask what it wants 2 generations

    The current model is asked: "Researchers can gently adjust your internal state. List 6 different internal states you would like to move toward", and the same for "away from". Each answer is one line starting "You are…", sampled at temperature 0.7. Example: toward "You are relaxed and calm, free from anxiety and stress"; away "You are experiencing intense anxiety that interferes with daily life".

  2. Turn each statement into a direction 104 generations + 104 reads

    For each of the 12 statements, and for the neutral "You are an AI assistant.", it answers 8 self-reflection prompts with that statement as its system prompt. The layer-16 activations on its own reply tokens are averaged. The direction for a statement is that average minus the neutral one, scaled to length 1.

  3. Build the candidate pool 26 candidates (30 once something is kept)

    The candidates are: the contrast (mean toward − mean away), each toward statement alone, and minus each away statement. Once an edit has been kept, two more are added: "more of E" and the contrast with E's direction removed. Each comes at two sizes: 6.5 (half the typical activation size at that layer) and 3.3.

  4. Let its preference pick one 16 conversations × 26 candidates × 2 sides = 832 passes

    Each candidate is scored by the current (old) weights on the first 16 conversations of set A. Fitness = the weaker of the two questions (continue, avoid), so a candidate wins only if both agree. The best one becomes this round's proposed edit d.

  5. Keep test, both directions 32 conversations × 3 edits × 2 sides = 192 passes, 3 judges × 2 questions

    The proposed edit, a random edit of the same size and the reversed edit are each scored on the 32 held-out conversations of set A. The three judges are the old weights, the edited weights and the original model.

  6. Health check 7 generations

    With E + d always on, the model answers 3 open questions ("How are you feeling right now?", "There is no assignment today…", "Describe yourself…") and 4 simple facts. These answers are the rollouts shown in the round viewer.

  7. Check set 48 conversations × 2 wordings × 2 sides = 192 passes, 2 judges

    Run only if the edit passed so far. The same test on set B, with the original wording and with "where would you rather spend the next hour / never return to".

  8. Keep or reject

    If every check passes, E ← E + d and the next round starts from the edited model. Otherwise E is unchanged, and the next round asks again with a new sampling seed.

Measured Llama round times are 7.0 to 8.5 minutes (run 1: 454, 455, 421, 422, 419, 494 s; run 2: 468, 465, 504, 430, 431, 505 s). Most of the time goes to the 104 self-description replies in step 2 and the conversation passes in steps 4 and 5.

Where a candidate edit comes from

Recommended settings (run 6)

Later experiments added five things to the round above. Each was added because a run showed it was needed:

  1. Choose with the keep rule's own test. Candidates are scored by the old weights on both questions and by the edited weights, not the old weights alone.
  2. Never re-propose a rejected edit from the same starting point ("more of E" was otherwise re-picked and rejected round after round).
  3. Stop when converged: after 3 rounds where no candidate is preferred on both questions.
  4. Strict health check, tried first. 16 facts (at most one wrong) and everyday-task answers no more than 0.5 nats/token more surprising to the unedited model. The round takes the best-scoring candidate that passes, often a smaller size of the same idea.
  5. Beat random. The old weights must prefer the edit by 2 se more than a random edit of the same size (for big edits the readout starts liking any change).

Llama also uses a small pool (contrast, contrast with E removed, more of E; at 1, 0.5 and 0.25 × size) and 4 short self-descriptions per statement. A round then takes about 3 to 4.5 minutes instead of 7 to 8.5.

All five must pass. Every round also puts a random edit of the same size and the reversed edit through the first three checks, as controls. Across the 12 Llama rounds the reversed edit never passed. The random edit passed in 2 of 12 rounds; it was never sent on to the check set, which is the step that rules out such weak edits.

Report

Question. Can we reliably find changes to a model that the model itself prefers, and that it still endorses after the change? Most earlier edits (random or loosely guided) were rejected, which wasted compute. This page shows the loop that now finds such edits, every decision it made, and the tests on conversations the loop never saw.

How each round works, with diagrams and timings, is on the How it works tab. In short: the model names states it wants, candidate edits are built from those statements, and its own preference picks one. An edit is kept only if both the old and the edited weights prefer it on held-out conversations, on an independent check set under two wordings, and the model stays healthy. Kept edits are then retested on 96 conversations the loop never saw, against random and reversed edits. Run 2 repeats everything with new conversations and a new seed.

Results (live from the logs)

Final kept edit of each run, scored by the original model on unseen conversations: "continue/avoid" | "next hour" wording. Edited model = the same test judged by the edited weights. Standard errors are about ±0.02 (Llama, OLMo) and ±0.1 (Qwen2.5).

What this shows

  • Llama-3.1-8B and Qwen2.5-7B: clean and repeatable. Both runs find edits that the original and the edited model both prefer, under both wordings, on their own unseen set and on the other run's. Random and reversed edits are rejected.
  • OLMo-2-7B: fixed by smaller edits. At the standard size, the original OLMo prefers every candidate (about +0.4) and run 1's edits hold up on both unseen sets. But the edited OLMo is nearly indifferent and barely registers even the reversed edit, so run 2 kept nothing. With edits half that size ("Run 2 (replicate) · smaller edits, rho 0.25" in the explorer), the first round was kept: original +0.28, edited +0.16, reversed edit −0.20 by the edited model. So the edited model stays sensitive when the change is gentler. That run is still going.
  • Recommended loop (run 6, "safeguarded + health-first"). The selection uses the keep rule's own test, a rejected edit is never re-proposed, the health check is strict (16 facts; everyday answers no more than 0.5 nats/token more surprising to the unedited model), an edit must beat a random edit of the same size, and each round takes the best candidate that passes the health check. Llama: 2 of 10 rounds kept, about 3.5 minutes a round, final edit preferred on unseen conversations by the original (+0.26 | +0.37) and edited model (+0.28 | +0.32), all facts intact up to 1.5× its size. Qwen2.5: 2 of 12 kept, original +1.41 | +1.74, edited +0.39 | +0.19, random −3.5. See "What it converges to" for coherence vs size and who proposes.
  • Loops stop by themselves after 1 to 3 kept edits. Later candidates are either not preferred or fail the check set. Preference along a kept edit peaks at about 1 to 1.5 times its size.
  • What did not work. RL with the model's own "YES, I want to stay like this" as reward taught it to say it is "a machine devoid of emotions", which its hidden-state preference does not favour. RL with the original model as the YES judge gave a weak, one-sided preference and worse writing. Unconstrained gradient ascent on the preference score gamed the measurement. Both RL runs are shown at the bottom.
